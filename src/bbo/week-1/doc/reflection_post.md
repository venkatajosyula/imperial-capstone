# Week 1 Reflection

What was the main principle or heuristic you used to decide on each query point (e.g. exploitation of high outputs, exploration of uncertain regions, diversity of samples)?
I mainly used a balanced exploitation strategy with a little exploration built in. I looked at the best-performing points for each function, then created the next query as a weighted mix of the top three inputs (60% from the best point, 30% from the second, 10% from the third). That helped me stay close to regions that already look promising, but still submit a genuinely new point instead of just copying the current best input. I also checked that each new point was not too close to an existing sample so it would still add information.

Which function(s) were most challenging to query, and why? What additional information would have helped you?
The hardest ones for me were Function 1 and the high-dimensional functions (especially Functions 7 and 8). For Function 1, the output values were extremely small and packed very tightly, so it was hard to tell what was a real signal versus just numerical scale. For Functions 7 and 8, the search space is much larger, so with limited samples I felt much less certain about where to query next. What would help most is uncertainty information for candidate points (for example from a GP), some indication of which input dimensions matter more, and a clearer view of which regions have already been explored enough.

How do you plan to adjust your strategy in future rounds based on the current performance or uncertainty levels?
In the next rounds, I want to make the exploration versus exploitation balance more adaptive for each function. If a function shows a clear improving trend in one region, I will keep exploiting locally around that area. If results look flat or noisy, I will deliberately explore farther away from the current top points. I also plan to test a few candidate queries with a simple surrogate model (for example, random forest or GP-style approximation) before choosing the final submission. My goal is to keep decisions practical and data-driven, but a bit more responsive to uncertainty than this first round.
